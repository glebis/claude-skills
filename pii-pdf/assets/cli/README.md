# pii-pdf · локальный CLI для агентов

Один PDF или папка → автоматический поиск персональных данных → JSON-события и, в режиме `redact`, изменённые копии PDF. Исходники не перезаписываются. Работает локально, не скачивает модели во время обработки и не задаёт интерактивных вопросов.

Текущая версия использует экспериментальный детектор предыдущего теста: spaCy PERSON, форматные правила и Tesseract. Известные ложные срабатывания на таблицах сохраняются. `exit 0` означает завершение обработки, **не подтверждение обезличивания**. Для каждого результата `validated: false`.

## Установка

Python 3.10+, Tesseract. Для предыдущего теста использованы PyMuPDF 1.26.6 (исторический тест; новый пакет требует исправленную версию >=1.26.7), spaCy 3.8.18 и модель en_core_web_sm 3.8.0.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m spacy download en_core_web_sm
.venv/bin/pii-pdf doctor
```

На macOS Tesseract устанавливается отдельно: `brew install tesseract`. Языковые пакеты тоже должны быть установлены заранее. Poppler нужен прежнему внешнему оценщику, но не этому CLI.

В текущем рабочем каталоге уже есть среда `work/pdf-env`; в ней можно запускать исходники без установки самого пакета:

```sh
work/pdf-env/bin/python outputs/pii-pdf-cli/pii-pdf schema
```

После установки в выбранную среду команды ниже доступны как `pii-pdf` при активированной среде. Альтернатива — `python -m pii_pdf`.

## Примеры

```sh
# Один файл: результаты и новый PDF в отдельной папке
pii-pdf redact statement.pdf --output ./redacted --json

# Каталог, включая подкаталоги; относительная структура сохраняется
pii-pdf redact ./statements --output ./redacted --recursive --json

# Только обнаружение: PDF не записывается, JSON возвращается в stdout
pii-pdf detect statement.pdf --json

# Проверить список входов и выходов без модели, OCR и записи
pii-pdf redact ./statements -o ./redacted --recursive --dry-run

# Машинное описание параметров и контракта
pii-pdf schema
pii-pdf --schema
pii-pdf redact --help --json

# Параметры OCR / типов данных / замены
pii-pdf redact statement.pdf -o ./redacted \
  --ocr-mode always --dpi 300 --psm 3 --language eng \
  --ocr-timeout 90 --model en_core_web_sm \
  --entities PERSON,ADDRESS,EMAIL,PHONE,IBAN,ACCOUNT \
  --padding 1 --max-font-size 9 --replacement synthetic

# Настройки из JSON; флаги имеют приоритет
pii-pdf redact statement.pdf -o ./redacted --config example-config.json --dpi 200

# Только удаление найденных областей, без новых синтетических строк
pii-pdf redact statement.pdf -o ./redacted --replacement blank
```

`--output` всегда каталог. Один файл `a.pdf` создаёт `OUTPUT/a.pdf`; папка с `sub/a.pdf` создаёт `OUTPUT/sub/a.pdf`. Только расширение `.pdf`, без учёта регистра. Поиск в папке пропускает symlink-файлы и выходной каталог, если он вложен во входной. Несколько одинаковых имён в разных подкаталогах не конфликтуют. Если выходной файл существует — ошибка до запуска обработки; повтор разрешается явно через `--overwrite`. Исходный файл нельзя перезаписать даже с этим флагом.

`detect` без `--output` не создаёт файлов. При `--output` сохраняет JSON-манифест. `--dry-run` не создаёт даже выходную папку.

## JSON-контракт

По умолчанию stdout — **NDJSON**: один самостоятельный JSON-объект на строку. `--json` явно закрепляет этот режим и допустим до или после команды. Обычный `--help` печатает текстовую справку; `--help --json` выдаёт JSON. Сообщения сторонних библиотек направляются в stderr.

Каждое событие содержит `schema_version`, `event`, `ts` (UTC ISO 8601), `run_id`, `seq`. Схема версии `1.0`. Основные события:

- `run_started`: число файлов, параметры, команда;
- `file_started`: входной и выходной пути;
- `file_result`: статус, количество кандидатов, найденные типы/координаты/замены;
- `error`: стабильный строковый `code`, сообщение, `retry`, `exit_code`;
- `summary`: обработано/ошибки/требуют проверки, код завершения, путь манифеста.

Пример итогового события (поля времени и идентификатора сокращены):

```json
{"schema_version":"1.0","event":"summary","ts":"...","run_id":"...","seq":4,"total":1,"attempted":1,"succeeded":1,"failed":0,"needs_review":0,"validated":false,"exit_code":0,"manifest":"/output/run-UUID.json"}
```

Агент должен ориентироваться на код завершения и `summary`; `file_started` не подтверждает успех. В ошибке до начала запуска будет только событие `error`, без `summary`. Если часть пакета обработана, уже созданные PDF сохраняются. `--fail-fast` останавливает пакет после первой ошибки; по умолчанию остальные файлы продолжают обрабатываться. Запись каждого PDF и манифеста атомарная, весь пакет атомарным не является.

Подробные результаты сохраняются в `OUTPUT/run-UUID.json`, обновляемом после каждого файла. Оригинальные значения PII и полный текст полей по умолчанию исключены из событий и манифеста; имена файлов, координаты и синтетические замены остаются. Для диагностики доступны `--include-sensitive` и `--save-evidence`: второй требует первый и `--output`, сохраняет OCR TSV с исходным текстом. Это диагностические материалы, содержащие исходные данные.

## Политики обработки

| Параметр | Значения | По умолчанию |
|---|---|---|
| `--ocr-mode` | `auto` — страницы с картинками, `always` — все, `never` — только текст | `auto` |
| `--replacement` | `synthetic`, `blank` | `synthetic` |
| `--metadata` | `strip`, `keep` | `strip` |
| `--attachments` | `error`, `drop`, `keep` — политика для неподдерживаемых вложений | `error` |

UTF-8 TXT-вложения обрабатываются детектором. Произвольные бинарные вложения не обезличиваются: `error` не создаст выходной PDF, `drop` удалит вложение из копии, `keep` сохранит его и отметит необходимость проверки. `--metadata keep` при наличии метаданных тоже требует проверки. `--ocr-mode never` при наличии изображений отмечает пропуск растрового поиска. Выбор неполного набора `--entities` ограничивает задачу, а не подтверждает отсутствие остальных типов PII.

Синтетические значения демонстрационные и детерминированные, возможны совпадения замен у разных людей. Это не обратимое соответствие идентичностей. Векторные контуры букв не удаляются, цифровые подписи/XFA не валидируются. Повороты и необычные страницы требуют отдельной проверки качества; CLI не заменяет прежний постфактум-оценщик.

## Коды завершения

| Код | Значение |
|---|---|
| 0 | Операция завершена; результат не валидирован |
| 1 | Внутренняя ошибка |
| 2 | Неверные аргументы, конфиг или входной путь |
| 3 | Зависимость или модель недоступна |
| 4 | Завершено, но есть явные необработанные места / сохранённые метаданные |
| 5 | Ошибка обработки одного или нескольких файлов; возможен частичный результат |
| 6 | Конфликт выходного пути / попытка перезаписать источник |
| 130 | Прерывание пользователем; завершённые ранее файлы могут остаться |

## Проверки

```sh
python -m unittest discover -s tests -v
```

Интеграционные тесты требуют зависимости, модель и Tesseract. Проверяются JSON ошибок/результатов, работа без зависимостей для schema/dry-run, защита исходников, повторный запуск, один файл/пакет/подпапки, фильтры сущностей, пустые замены, OCR и политики вложений. Проверки CLI не измеряют полноту детектора на новых документах.

Сторонние библиотеки сохраняют свои лицензии, включая лицензирование PyMuPDF.
